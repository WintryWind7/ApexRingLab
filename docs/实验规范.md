# 实验规范

> 供 AI 快速理解框架设计和使用规范

## 框架设计理念

**渐进式实验框架**：
1. 统一基础设施（数据、训练、评估）
2. 实验独立性（互不干扰）
3. 低摩擦实验（最少只需写 3 个文件）
4. 结果可对比（统一评估标准）

**面向接口的评估体系**：
- **核心思想**：Evaluator 只依赖 Predictor 接口，不关心模型内部实现
- **通用性**：无论模型类型（MLP、GAN、扩散模型、分类器等），只要实现 Predictor 接口，就能自动接入评估体系
- **职责分离**：
  - Model：专注于前向传播（张量 → 张量）
  - Predictor：接口适配层（字典 → 张量 → 字典），处理坐标归一化和格式转换
  - Evaluator：通用评估逻辑，只调用 Predictor.predict()
- **好处**：新模型无需修改评估代码，只需实现 Predictor 即可

## 核心架构

### 三个必需文件

```
experiments/<实验名>/
├── <模型名>.py       # 继承 BaseModel/VectorModel/ImageModel，实现 forward()
├── predictor.py      # 继承 Predictor，实现 predict() - 必须正确实现！
└── train.py          # 调用 Trainer，必须启用自动评估
```

**关键要求**：
1. **Predictor 必须正确实现**：
   - 输入输出都是原始像素坐标（字典格式）
   - 内部处理所有归一化、坐标转换、地图编码
   - 这是评估体系的唯一接口，实现错误会导致评估失败
   
2. **train.py 必须启用自动评估**：
   ```python
   trainer = Trainer(
       ...,
       predictor_class=YourPredictor,  # 必须传入
       test_loader=test_loader,         # 必须传入
       auto_evaluate=True               # 默认开启
   )
   ```
   - 训练完成后自动评估并将结果写入 pth
   - 不启用自动评估的模型无法参与对比

### 多版本模型管理

**同一实验的多个模型版本写在同一个 model.py 文件中**：

```python
# experiments/mlp_deep/mlp_deep.py

class MLPDeep(VectorModel):
    """深层MLP - 基础版本"""
    pass

class MLPDeepV2(VectorModel):
    """深层MLP V2 - 更深层次"""
    pass

class MLPDeepV3(VectorModel):
    """深层MLP V3 - 添加 BatchNorm"""
    pass
```

**命名规则**：
- 基础版本：描述性名称（如 `MLPDeep`）
- 迭代版本：添加 `V2`, `V3` 后缀（如 `MLPDeepV2`）
- 或使用描述性名称（如 `MLPVeryDeep`, `MLPDeepBatchNorm`）

**自动隔离**：
- Trainer 按类名自动创建子目录：`checkpoints/MLPDeep/`, `checkpoints/MLPDeepV2/`
- 每个版本的模型、训练历史、评估结果独立保存

### 职责分离

- **Model**：前向传播，输入输出都是张量
  - 只关心张量计算
  - 不处理坐标归一化、地图编码等
  
- **Predictor**：接口适配层，处理格式转换（字典↔张量）和坐标归一化/反归一化
  - 统一接口：`predict(map_name, ring1_data, ring2_data=None) -> (ring2_dict, ring3_dict)`
  - 输入输出都是原始像素坐标字典
  - 内部调用 Model 并处理所有转换
  
- **Evaluator**：通用评估逻辑
  - 只调用 `Predictor.predict()`
  - 不关心模型类型、坐标模式、地图编码方式
  - 对所有模型使用相同的评估逻辑
  
- **Trainer**：统一训练流程，自动评估
  - 训练完成后自动调用 Evaluator
  - 将评估结果写入 pth 文件

**Predictor 存在的原因**：
- 让 Evaluator 保持通用，不需要为每个实验修改代码
- 无论模型内部如何实现（绝对坐标/相对坐标、One-Hot/Embedding、回归/分类），Evaluator 都能正常工作
- 这是面向接口编程的典型应用

## 框架组件

**统一基础设施**（`model/` 目录，禁止修改）：
- `base.py` - 模型基类
- `predictor.py` - 预测器基类
- `dataset.py` - 自回归数据集
- `trainer.py` - 统一训练器
- `evaluator.py` - 评估器
- `loss.py` - 损失函数库
- `comparator.py` - 模型对比工具

**工具**（`utils/` 目录）：
- `model_inspector.py` - 命令行工具

**扩展规则**：
- 框架有的直接用
- 框架没有的在实验目录维护：
  - 自定义 Loss：在实验目录创建 `loss.py`
  - 自定义 Dataset：在实验目录创建 `dataset.py`
  - 特殊训练逻辑（如 GAN 对抗训练）：自定义训练循环

## Trainer 关键参数

**基础**：
- `model`, `train_loader`, `val_loader`, `loss_fn`, `optimizer`, `scheduler`
- `save_dir` - Trainer 自动创建 `save_dir/<ModelName>/` 子目录

**坐标模式**：
- `coordinate_mode` - `"absolute"` 或 `"relative"`
- `use_onehot` - 是否使用地图 One-Hot 编码
- `extra_feature_dims` - 额外特征维度
- `compute_scenario_errors` - 是否在训练时计算场景误差（默认 False）

**自动评估**：
- `auto_evaluate=True` - 默认开启
- `predictor_class` - Predictor 类
- `test_loader` - 测试数据加载器

**自动评估流程**：加载最佳模型 → 创建 Predictor → 评估 → 写入 test_metrics 到 pth

**注意**：可视化需手动调用 `Evaluator.visualize_predictions()`

## 评估体系

**两种场景**：
- 场景1：Ring1 → 预测Ring2 → 预测Ring3（误差累积）
- 场景2：Ring1 + 真实Ring2 → 预测Ring3（理想情况）

**pth 结构**：
```python
{
    "model_name": "...",
    "model_state_dict": {...},
    "epoch": 42,
    "optimizer_state_dict": {...},
    "metrics": {  # 训练指标
        "best_val_loss": ...,
        "best_epoch": ...,
        "history": {...}
    },
    "test_metrics": {  # 测试指标（顶层）
        "evaluated_at": "...",
        "test_dataset_version": "...",
        "metrics": {
            "scenario_1_only_ring1": {...},
            "scenario_2_ring1_and_ring2": {...}
        }
    }
}
```

**模型对比**：
```bash
# 列出所有模型
python utils/model_inspector.py list

# 查看单个模型
python utils/model_inspector.py view path/to/model.pth

# 对比模型（2个或更多）
python utils/model_inspector.py compare path1.pth path2.pth [path3.pth ...]

# 对比并指定名称
python utils/model_inspector.py compare path1.pth path2.pth -n Name1 Name2
```


## 数据格式

**坐标系统**：16384 × 16384，归一化到 0-1

**模型输入**（使用 One-Hot）：
- `[map_onehot(2), ring1(3), ring2_rel(3)]` = 8 维

**模型输出**（相对坐标）：
- `[dx, dy, r]` = 3 维

## Predictor 接口

**构造函数**：
```python
def __init__(self, model, device: str = "cuda", grid_size: int = 16384):
    super().__init__(device, grid_size)
    self.model = model.to(device)
    self.model.eval()
```

**必须实现**：
```python
def predict(
    self, 
    map_name: str,
    ring1_data: Dict,  # {"x": x1, "y": y1, "r": r1} (原始像素坐标)
    ring2_data: Optional[Dict] = None
) -> Tuple[Dict, Dict]:  # (ring2_dict, ring3_dict) (原始像素坐标)
```

**关键点**：
- 输入输出都是原始像素坐标
- Predictor 内部处理归一化/反归一化
- 模型输出相对坐标，Predictor 负责转换为绝对坐标
- `ring2_data` 为 None 时预测 Ring2 和 Ring3，否则只预测 Ring3

**典型实现**：
1. 归一化输入坐标（除以 grid_size）
2. `map_name` → One-Hot 编码
3. 构造输入：`[map_onehot, ring1, ring2_rel]`
4. 调用模型获取相对坐标：`[dx, dy, r]`
5. 转换为归一化绝对坐标：`x_abs = x_prev + dx`
6. 反归一化（乘以 grid_size）并返回原始坐标字典

## 关键规范

1. **三个文件必需**：model.py, predictor.py, train.py

2. **必须继承基类并实现对应方法**

3. **Predictor 接口统一**：
   - 输入输出都是原始像素坐标字典
   - 内部处理所有归一化、坐标转换、地图编码
   - 这是评估体系的唯一接口，必须正确实现

4. **train.py 必须启用自动评估**：
   - 传入 `predictor_class` 和 `test_loader`
   - 保持 `auto_evaluate=True`（默认值）
   - 训练完成后自动评估并写入 pth

5. **不修改框架代码**：
   - 优先使用框架提供的组件（loss, dataset, trainer）
   - 需要自定义 loss 或 dataset 时在实验目录创建
   - 特殊训练逻辑（如 GAN）可自定义训练循环

6. **自包含原则**：实验目录包含所有相关代码和结果
